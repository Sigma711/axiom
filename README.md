# AXIOM

AXIOM 是一套用来学习量化交易开发的本地学习平台。它不替你找“稳赚策略”，而是把一套策略从行情、假设、信号、风控、回测到模拟执行的过程摊开，让刚开始写量化程序的人知道每个数字从哪里来、该信什么、该怀疑什么。

> 仅供学习。页面上的回测和模拟盘都不发送真实订单。

## 你可以在这里做什么

- 在**指标大全**读懂常见指标、财务比率、量价概念和 K 线形态。每个条目都有定义、例子、图示和适用边界；实践页面会说明用的是当前行情，还是需要额外证据的教学输入。
- 在**数据探索**查看行情、叠加指标、识别形态，再用当前数据亲手计算概念。
- 在**回测**设定策略、交易对、资金、仓位和止盈止损，查看净值、交易记录、回撤和风险调整后的收益。
- 在**模拟盘**观察同一套事件链如何处理信号、成交、持仓和净值变化。
- 在**策略对比**让多套策略使用同一段行情和相同初始资金，避免拿不同样本硬比结果。
- 在**学习中心**按学习路径读源码；“原书阅读”提供《股票交易软件专业指标全解》的目录式阅读。

## 第一次使用

启动服务后打开 <http://localhost:8080>：

```sh
make serve
```

建议按这个顺序走一遍：

1. 打开学习中心的**概念速览**，先看完整流程。记住一条底线：当前 K 线产生的信号，最早只能在下一次可交易时点执行。
2. 到**数据探索**选一个熟悉的交易对。先看 K 线，再叠加一个趋势指标和一个振荡指标；不要急着把指标当作买卖按钮。
3. 回到**指标大全**，展开一个概念，进入它标出的适用实践页面。先看数据来源和适用条件，再看数值。
4. 到**回测**运行一个简单策略。优先看最大回撤、交易次数和成本，再看总收益率。
5. 用**策略对比**把基准和两三个策略放在同一份数据上比较。若只换一个参数就从亏损变暴利，先怀疑样本和过拟合。
6. 最后启动**模拟盘**。它适合检查事件顺序和账户状态，不等于实盘表现。

## 怎样读回测结果

回测回答的是“在这段历史、这些规则和这些成本假设下，会发生什么”，不是“下次一定会怎样”。

- **总收益**：这段样本中资金的变化。
- **最大回撤**：从高点跌到低点最难熬的一段。收益相近时，回撤往往更值得比较。
- **夏普、索提诺、Calmar**：把收益和波动或回撤放在一起看。它们用于比较，不是通行证。
- **交易笔数和胜率**：胜率高不代表好策略；还要看每次盈亏、费用和亏损是否集中。
- **净值曲线**：平滑不等于可靠。关注它是否只靠少数交易、是否有长时间停滞，以及换一段数据后是否还成立。

页面显示“—”时，意思通常是样本不足或该指标无定义，不是零。

## 量化开发里最容易踩的坑

- 把尚未收盘的价格、未来数据或后来修订的数据带进历史计算。
- 只挑一段表现最好的行情，再不断调参数直到曲线漂亮。
- 忽略手续费、滑点、成交延迟和仓位上限。
- 用多个高度相关的指标当作“多重确认”。
- 把研究阶段的机器学习或大模型输出直接当成订单。它们可以帮助整理资料、构造特征和检查假设，但仍要经过数据校验、回测和风控。

## 学习路径

从最小的一条链开始：

`行情 → 指标/特征 → 信号 → 风控与仓位 → 订单与成交 → 净值与复盘`

学习中心里的每一步都附有动手任务和 GitHub 精确源码链接。链接由构建时的源码符号生成，并固定到对应提交；代码移动后重新构建会重新定位，不依赖手写行号。

历史行情目前使用 CSV 缓存，模拟盘状态在进程内存中。数据量和研究需求增长后，才值得把不可变历史数据放进 Parquet、用 DuckDB 做批量分析，并用 SQLite 保存需要恢复的本地状态；先把四种存储都搬进来只会增加学习和维护成本。

## 常用命令

```sh
make setup   # 首次安装依赖
make serve   # 构建并启动学习平台
make test    # 运行全部测试
make ci      # 运行与持续集成相同的检查
```
