概念速览

量化交易的完整流程

从原始行情到最终下单,一个量化系统走完下面 7 步。后面"每个概念"小节会拆开讲每一步。

              原始数据            指标计算            交易信号            风控过滤            仓位计算            模拟执行            业绩评估

  [OHLCV  K线]  →  [SMA / MACD /  ...]  →  [BUY / SELL / HOLD]  →  [止损 / 仓位上限]  →  [买多少 / 卖多少]  →  [模拟券商]  →  [收益 / 回撤 / 夏普]
        ↑              ↑                    ↑                    ↑                    ↑                    ↑                    ↑
   Binance API     纯函数            只产生想法           兜底安全           按风险调仓            手续费/滑点        数字不会说谎
   CSV 文件        无副作用            不下单              防止黑天鹅         Kelly / 固定比例        与实盘接口一致      看穿策略真相

为什么每一步都重要

步骤作用如果跳过会怎样
1. 原始数据所有决策的输入垃圾进,垃圾出
2. 指标计算把价格变抽象成"可比较的数"凭感觉交易
3. 交易信号策略的"想法"无法程序化
4. 风控过滤活下来一次黑天鹅归零
5. 仓位计算控制单笔风险信号对了也亏光
6. 模拟执行真实还原交易成本回测漂亮实盘亏
7. 业绩评估判断策略好坏只看收益率,被回撤坑死

进阶:每一步都有专门的学科

1. 数据 — 数据清洗、复权处理、Tick 数据 vs 分钟数据、数据库选型
2. 指标 — 200+ 技术指标(本项目实现了 50+)、数学公式、参数选择
3. 信号 — 趋势跟踪 / 均值回归 / 套利 / 高频做市 / 机器学习预测
4. 风控 — VaR / CVaR / 凯利公式 / 最大回撤约束 / 压力测试
5. 仓位 — 固定比例 / 波动率倒数加权 / 风险平价
6. 执行 — TWAP / VWAP / 冰山订单 / 滑点模型 / 撮合机制
7. 评估 — 夏普 / 索提诺 / Calmar / 信息比率 / 多因子归因

每个概念对应一个代码模块

下面 9 张卡是这个项目里最核心的"概念",每个都对应 src/ 里一个文件。

K线 (Bar)

一根柱子记录一段时间的开 / 高 / 低 / 收 / 成交量。

{ ts, open, high, low, close, volume }

信号 (Signal)

策略看到行情后的想法:BUY / SELL / HOLD。

{ side, strength, reason }

订单 (Order)

给券商的具体指令:方向、数量、价格。

{ side, size, price, type }

成交 (Fill)

订单实际被执行的回报,扣手续费和滑点。

{ size, price, commission }

持仓 (Position)

你现在持有多少某个标的,以及平均成本。

{ size, avg_entry_price }

净值 (Equity)

总身家:现金 + 持仓按当前价估值。

cash + position × price

风控 (Risk)

止损 / 止盈 / 仓位上限 —— 活下来比赚得多重要。

{ stop_loss, take_profit, max_pos }

指标 (Metrics)

总收益 / 最大回撤 / 夏普比率。

{ total_return, max_dd, sharpe }

回测 / 模拟盘 / 实盘

同一套策略,换不同的券商 adapter,就能在历史 / 实时 / 真金白银上跑。

SimulatedBroker / HttpFeed / LiveBroker

创建自己的策略

从"想赚钱"到"能稳定赚钱"需要走完下面 5 步。每一都不能跳过。

  1. 形成可验证的市场假设

    每个好策略背后都有一句话能说清楚的假设:

    • ❌ "我觉得 BTC 要涨" —— 不可验证
    • ✅ "BTC 在 20 日新高 + 成交量放大 → 接下来 5 天继续上涨概率 > 60%" —— 可验证

    好的假设包含三要素:

    • 时间维度: 短期(日内) / 中期(数天) / 长期(数月)
    • 方向判断: 看涨 / 看跌 / 震荡
    • 反证条件: 什么情况下假设错了

  2. 选择指标来验证假设

    用指标验证你的假设,不是凭感觉猜。

    你的假设用这些指标验证
    趋势在持续SMA / EMA / MACD / DMI
    价格超跌会反弹RSI / KDJ / Bollinger
    量能决定真假OBV / CMF / MFI
    突破关键位Donchian / Bollinger / Volume Profile
    波动率即将爆发BBands Squeeze / ATR

    💡 不要用 5 个振荡器(RSI、KDJ、Williams %R 本质都是动量指标,信息冗余)。

  3. 定义无歧义信号

    入场信号 (好)
    • RSI 从 < 30 反弹到 > 30 → BUY
    • SMA5 上穿 SMA20 → BUY
    • 收盘突破 20 日 Donchian 高点 → BUY
    • MACD DIF 上穿 DEA → BUY
    入场信号 (差)
    • "感觉要涨了"
    • "价格低了点"
    • "几个指标都指向 BUY"
    • "专家说要涨"

  4. 写代码

    打开 src/strategy.rs,找一个最像的现有策略,复制骨架。

    pub struct MyStrategy {
    history: History,
    period: usize,
    threshold: f64,
    prev_state: Option<f64>,
}

impl Strategy for MyStrategy {
    fn name(&self) -> &str { "my_strategy" }
    fn params(&self) -> HashMap<String, f64> { /* ... */ }
    fn on_bar(&mut self, bar: &Bar) -> Signal {
        self.history.push(bar);
        if self.history.bars.len() < self.period {
            return Signal::hold("等待预热");
        }
        let sma = self.history.sma(self.period).unwrap();
        if bar.close > sma * (1.0 + self.threshold) {
            Signal::buy("价格突破均线")
        } else if bar.close < sma * (1.0 - self.threshold) {
            Signal::sell("价格跌破均线")
        } else {
            Signal::hold("震荡中")
        }
    }
    fn reset(&mut self) { self.history.reset(); }
}

    完整模板参考 src/strategy.rs 里的 SmaCrossStrategy 或 RsiStrategy。

  5. 测试和迭代

    跑回测前问自己:

    • 样本外验证: 有没有用回测数据之外的真实数据测过?
    • 参数来源: 参数是按常识选的还是优化出来的?
    • 心理承受力: 最大回撤你能接受吗?

    回测后看这些指标(不要只盯总收益):

    指标含义合格线
    夏普比率每单位风险换多少收益> 1
    索提诺比率只看下行波动> 1.5
    最大回撤最惨时亏多少< 20%
    Calmar年化 / 最大回撤> 1
    胜率 × 盈亏比期望收益> 1

常见陷阱

低 PE ≠ 便宜

周期股 PE 低可能是周期顶点(利润即将下滑)。

RSI 超买 ≠ 卖出

强趋势中 RSI 可长期 > 70。反向交易 RSI 会被反复止损。

金叉 ≠ 领先信号

金叉发生在趋势已确立之后(滞后)。用金叉抓顶/底 = 迟到。

多个振荡器 ≠ 多重确认

RSI、KDJ、Williams %R 本质都是动量指标,叠加不增加信息。

主力净流入 ≠ 真现金流入

只是统计主动买入单。主力可拆单对倒伪装净流入。

参数没有神圣数字

MA(20)、RSI(14) 不是天经地义的。必须做参数敏感性分析。

进阶话题

  • 仓位管理: 固定比例、Kelly Criterion、波动率倒数加权
  • 多策略组合: 不同策略在不同时期表现不同,组合可以平滑收益曲线
  • 参数优化陷阱: 在历史数据上优化出的参数,在未来几乎一定失效。用 walk-forward analysis。
  • 市场状态识别: 同一个策略在趋势市和震荡市表现可能完全相反

源码阅读顺序

按这个顺序读代码,最快搞懂整个系统。

  1. 1. src/types.rs —— 词汇表

    先搞懂每个类型(Bar / Order / Fill / Position / Trade)代表什么。这是后续一切的基础。

  2. 2. src/broker.rs —— 模拟券商

    理解"为什么同一个策略能在回测/模拟盘/实盘复用"—— 因为 Broker 是个 trait,背后可以换不同实现。

  3. 3. src/strategy.rs —— 策略

    看双均线、RSI 策略的代码,理解"为什么策略只产生 Signal 而不下单"—— 这是系统解耦的关键。

  4. 4. src/portfolio.rs + src/risk.rs —— 仓位与风控

    策略说"买",组合说"买多少",风控说"不能买"。

  5. 5. src/engine.rs —— 主循环

    回测引擎按"K线一根一根"地推进整个系统。

  6. 6. src/metrics.rs —— 评判标准

    不要只盯着收益率。看最大回撤、夏普、Sortino。

  7. 7. src/indicators/*.rs —— 指标库

    所有指标的纯函数实现。SMA、RSI、布林带、MACD、一目均衡表都在这。

  8. 8. src/paper.rs + src/api.rs —— 接口和前端

    REST 和 WebSocket 是怎么把后端能力暴露给浏览器的。
